- **interface** → для описания объектов, классов, может наследоваться и расширяться.
- **type** → универсален: можно описывать примитивы, объединения, пересечения. Более гибкий, но не поддерживает множественное расширение как интерфейс.

---

## 🔹 Подробный ответ

### 1. Общие черты

И `type`, и `interface` позволяют описывать **структуру данных**:

```ts
interface IUser {
  name: string;
  age: number;
}

type User = {
  name: string;
  age: number;
};
```
Оба варианта равнозначны для объектов.

---

### 2. Отличия

### 🔸 Где использовать

- `interface` → удобнее для **объектов и классов**, т.к. поддерживает `extends` и декларативное расширение.
- `type` → более универсален, может описывать:
    - примитивы (`type ID = string | number`)
    - объединения (`type Shape = Circle | Square`)
    - пересечения (`type A = B & C`)
    - кортежи (`type Pair = [string, number]`)

---

### 🔸 Расширение
```ts
interface A { x: number }
interface B extends A { y: number }

type A = { x: number }
type B = A & { y: number }
```
⚡ Разница: interface можно расширять декларативно (повторным объявлением), type так не умеет.
interface:
```ts
interface User { name: string }
interface User { age: number } // ✅ объединит оба интерфейса
```
type:
```ts
type User = { name: string }
type User = { age: number }   // ❌ ошибка: повторное объявление
```

### 🔸 Композиция

- `type` поддерживает **union и intersection**:

```ts
type Status = "success" | "error" | "loading";
type WithId = { id: number };
type User = WithId & { name: string };
```

- `interface` так не умеет (только наследование).

---

### 3. Рекомендации

- Для API/объектов/классов → **interface**.
- Для сложных типов, примитивов, union/intersection → **type**.
- В целом, **интерфейсы больше для декларативных структур, type — для гибкой типизации**.

---

✅ **Итог:**

- `interface` → расширяемый, декларативный, лучше для ООП-структур.
- `type` → гибкий, универсальный, поддерживает union/intersection.
