- Через **`try...catch`**.
- Использую `Error` для типизации.
- Линтер + строгий компилятор (`strict`, `noImplicitAny`).
- Для async — **`.catch()` у промисов** или `try...catch` с `async/await`.

---

## 🔹 Подробный ответ

### 1. Синхронные ошибки

```tsx
try {
  const result = riskyOperation();
  console.log(result);
} catch (error) {
  if (error instanceof Error) {
    console.error("Ошибка:", error.message);
  }
}

```

---

### 2. Асинхронные ошибки

С `async/await`:

```tsx
async function fetchData() {
  try {
    const res = await fetch("<https://api.com/data>");
    return await res.json();
  } catch (error) {
    if (error instanceof Error) {
      console.error("Ошибка загрузки:", error.message);
    }
  }
}

```

С `Promise.catch`:

```tsx
fetch("<https://api.com/data>")
  .then(res => res.json())
  .catch((error: Error) => console.error("Ошибка:", error.message));

```

---

### 3. Уровень TypeScript

- Включаю строгий режим в `tsconfig.json`:

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true}
}

```

- Это позволяет **ловить ошибки ещё на этапе компиляции**, до запуска кода.

### 4. Дополнительно

- Использую **ESLint** + **TypeScript ESLint** для статического анализа.
- В больших проектах — глобальный обработчик ошибок (`window.onerror`, `process.on("uncaughtException")`).
