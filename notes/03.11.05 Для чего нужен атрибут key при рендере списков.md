`key` — это **уникальный идентификатор элемента списка**.

React использует его, чтобы правильно отслеживать и обновлять элементы при перерисовке списка.

---

## 🔹 Подробный ответ

### 1. Зачем нужен `key`?

- При изменении массива (добавление, удаление, перестановка элементов) React сравнивает **старый Virtual DOM** с новым.
- Если у элементов нет ключей, React обновляет их "по порядку", что может привести к:
    - неправильному сохранению состояния,
    - лишним перерисовкам,
    - багам в UI.
- `key` помогает React **точно понять, какой элемент изменился**.
### 2. Пример без key

```js
const items = ["a", "b", "c"]; 
	<ul> {items.map(item => <li>{item}</li>)}</ul>
```
⚠ React будет ругаться: "Each child in a list should have a unique key...".

### 3. Пример с key

```js
const items = ["a", "b", "c"]; 
<ul> 
{items.map((item, index) => <li key={index}>{item}</li>)}
</ul>
```

✅ Теперь React знает, какой элемент какой.

---

### 4. Почему `index` — не всегда хороший `key`?

- Если элементы списка **меняются местами**, `index` остаётся прежним → React может неправильно обновить UI.
- Лучше использовать **уникальный ID** из данных:
```js
users.map(user => <li key={user.id}>{user.name}</li>);
```

✅ **Итог:**

Атрибут `key` нужен, чтобы React **правильно сопоставлял элементы списка** при изменениях и не ломал их состояние. Лучше использовать уникальные ID, а `index` — только как запасной вариант.
