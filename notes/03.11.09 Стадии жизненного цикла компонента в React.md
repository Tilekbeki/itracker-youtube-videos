Жизненный цикл классового компонента делится на 3 стадии:

1. **Mounting (Монтирование)** → `constructor`, `render`, `componentDidMount`.
2. **Updating (Обновление)** → `render`, `componentDidUpdate`.
3. **Unmounting (Размонтирование)** → `componentWillUnmount`.

В функциональных компонентах — всё через **хуки (`useEffect`)**.

---

## 🔹 Подробный ответ

### 1. Mounting (Монтирование)

Когда компонент создаётся и вставляется в DOM.

- `constructor` → инициализация state.
- `render` → возврат JSX.
- `componentDidMount` → вызывается один раз после рендера, можно делать запросы к API.

---

### 2. Updating (Обновление)

Когда изменяются `props` или `state`.

- `render` → перерисовка компонента.
- `componentDidUpdate(prevProps, prevState)` → вызывается после обновления, удобно для сетевых запросов и синхронизации.

---

### 3. Unmounting (Размонтирование)

Когда компонент удаляется из DOM.

- `componentWillUnmount` → очистка таймеров, отписка от событий, отмена запросов.
### 4. Функциональные компоненты (Hooks)

Вместо методов жизненного цикла используется `useEffect`:

```jsx
useEffect(() => {
  console.log("Монтирование или обновление");

  return () => {
    console.log("Размонтирование");
  };
}, [deps]);

```

- Без deps → вызывается при каждом рендере.
- С пустым массивом `[]` → аналог `componentDidMount` + `componentWillUnmount`.
- С зависимостями `[a, b]` → вызывается при изменении этих значений.

---

### 5. Схема (для собеса за 20 секунд)

**Mounting → Updating → Unmounting**

- Mount: `constructor`, `render`, `componentDidMount`
- Update: `render`, `componentDidUpdate`
- Unmount: `componentWillUnmount`
- В функциональных компонентах всё делается через `useEffect`.
