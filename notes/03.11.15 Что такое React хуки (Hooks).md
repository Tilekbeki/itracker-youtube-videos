**Hooks** — это функции, добавленные в React 16.8, которые позволяют использовать **состояние (state)** и **жизненный цикл** в функциональных компонентах, без классов. Примеры: `useState`, `useEffect`, `useContext`.

---

## 🔹 Подробный ответ:

### 1. **Зачем нужны хуки**

До React 16.8 для работы со `state` и методами жизненного цикла приходилось использовать классы. Хуки позволяют:

- хранить состояние внутри **функциональных компонентов**,
- использовать побочные эффекты,
- переиспользовать логику между компонентами.

---

### 2. **Основные хуки**

- **`useState`** — локальное состояние.
- **`useEffect`** — побочные эффекты (запросы, таймеры, подписки).
- **`useContext`** — доступ к контексту.
- **`useReducer`** — управление сложным состоянием.
- **`useMemo`** — мемоизация значений.
- **`useCallback`** — мемоизация функций.
- **`useRef`** — доступ к DOM-элементам и хранение mutable-значений.
### 3. **Пример**
```js
import React, { useState, useEffect } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Счётчик: ${count}`;
  }, [count]); // эффект срабатывает при изменении count

  return (
    <button onClick={() => setCount(count + 1)}>
      Нажали {count} раз
    </button>
  );
}
```

### 4. **Правила хуков**

1. Хуки вызываются **только на верхнем уровне** (не в условиях, циклах, вложенных функциях).
2. Хуки вызываются **только внутри функциональных компонентов** или **кастомных хуков**.

---

### 5. **Плюсы хуков**

- Упрощают код → меньше классов.
- Легче разделять и переиспользовать бизнес-логику (через кастомные хуки).
- Код становится более декларативным.

**Минусы:**

- Легко нарушить правила хуков (требует внимательности).
- Иногда сложнее дебажить, чем классовые методы.
