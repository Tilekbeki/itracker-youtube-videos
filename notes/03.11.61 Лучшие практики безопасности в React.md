1. **Не вставлять HTML через `dangerouslySetInnerHTML` без очистки**.
2. **Экранировать пользовательский ввод** (React делает это автоматически при JSX).
3. **Использовать HTTPS** для API и ресурсов.
4. **Не хранить секреты в коде или client-side**.
5. **Защита от CSRF/Clickjacking** через токены, заголовки и Content Security Policy (CSP).

---

## 🔹 Подробный ответ

### 1. XSS (Cross-Site Scripting)

- React автоматически экранирует строки в JSX:
```js
const userInput = "<script>alert('XSS')</script>";
<div>{userInput}</div> // безопасно, выводится как текст
```
- ⚠️ Опасно: `dangerouslySetInnerHTML` без очистки.
- Решение: использовать **библиотеки для очистки HTML**, например `DOMPurify`.

---

### 2. CSRF (Cross-Site Request Forgery)

- Защищаемся через **токены** и **заголовки авторизации** при запросах к API.

---

### 3. Clickjacking

- Настройка заголовков **X-Frame-Options** или **CSP frame-ancestors** на сервере.

---

### 4. HTTPS

- Используем **шифрованное соединение** для всех ресурсов и API.

---

### 5. Безопасность state и секретов

- Не хранить **API ключи, пароли, токены** в коде или localStorage без шифрования.

---

### 6. Обновления зависимостей

- Следить за **уязвимыми пакетами** (`npm audit`, Dependabot).

---

### 7. Дополнительно

- Ограничить использование сторонних библиотек для DOM-манипуляций.
- Минимизировать работу с `eval()` и `Function()` конструкциями.
