## 🔹 Краткий ответ (для собеса):

- **Интерфейс (interface)** → описывает **только структуру** (типы свойств и методов), не содержит реализации.
- **Абстрактный класс (abstract class)** → может содержать **реализацию методов**, но сам не может быть инстанциирован.

---

## 🔹 Подробный ответ

### 1. Интерфейс (`interface`)

- Определяет **контракт**, который должен соблюдать класс.
- Можно наследовать несколько интерфейсов одновременно.
- Не генерирует код в JS.

```tsx
interface IShape {
  color: string;
  area(): number;
}

class Circle implements IShape {
  constructor(public color: string, public radius: number) {}
  area(): number {
    return Math.PI * this.radius ** 2;
  }
}

```

---

### 2. Абстрактный класс (`abstract class`)

- Может содержать **реализованные методы и свойства**.
- Можно наследовать только **один абстрактный класс**.
- Нельзя создавать экземпляр напрямую.

```tsx
abstract class Shape {
  constructor(public color: string) {}
  abstract area(): number; // обязательно реализовать в наследнике
  describe() {
    console.log(`This shape is ${this.color}`);
  }
}

class Circle extends Shape {
  constructor(color: string, public radius: number) {
    super(color);
  }
  area(): number {
    return Math.PI * this.radius ** 2;
  }
}

```

---

### 3. Отличия

|Особенность|Интерфейс (`interface`)|Абстрактный класс (`abstract class`)|
|---|---|---|
|Содержит реализацию|❌ Нет|✅ Можно|
|Можно создавать экземпляр|❌ Нет|❌ Нет|
|Наследование|✅ Несколько интерфейсов|✅ Только один класс|
|Генерирует код в JS|❌ Нет|✅ Да (как обычный класс)|
|Использование|Контракт / типизация|Базовый класс с частичной реализацией|

---

✅ **Итог:**

- **Интерфейс** → декларация структуры.
- **Абстрактный класс** → частичная реализация + структура.
- Используем интерфейс для контрактов и множественного наследования, абстрактный класс — когда нужна общая реализация.
