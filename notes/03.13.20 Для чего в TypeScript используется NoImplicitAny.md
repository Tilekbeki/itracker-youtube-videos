Флаг **`noImplicitAny`** в `tsconfig.json` запрещает неявное присвоение типа `any`.

- Если компилятор не может вывести тип, он **заставит явно указать тип**, вместо того чтобы автоматически подставлять `any`.

---

## 🔹 Подробный ответ

### 1. По умолчанию (без `noImplicitAny`)

TypeScript позволяет оставлять параметры и переменные без типа → им присваивается `any`.

```tsx
function log(message) { // message: any
  console.log(message);
}

```

⚠️ Проблема: теряется смысл статической типизации → ошибки будут только в рантайме.

---

### 2. С `noImplicitAny: true`

Компилятор выдаст ошибку, если не может определить тип.

```tsx
function log(message) {
  // ❌ Error: Parameter 'message' implicitly has an 'any' type.
  console.log(message);
}

```

👉 Решение: нужно указать тип явно:

```tsx
function log(message: string) {
  console.log(message);
}

```

---

### 3. Где полезно

- В **больших проектах**, где легко потерять контроль над типами.
- Помогает писать **более безопасный и предсказуемый код**.
- Заставляет разработчика быть внимательнее при проектировании API функций.

---

✅ **Итог:**

`noImplicitAny` — это флаг, который **запрещает скрытый `any`**, чтобы сохранить пользу от строгой типизации и избежать ошибок в рантайме.
